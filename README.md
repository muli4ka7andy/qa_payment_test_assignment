# Тестовое задание QA/SDET

## Состав решения

- `api/` — black-box API-тесты, HTTP-клиент и фабрика тестовых данных;
- `reconciliation/` — загрузка CSV в SQLite и SQL-запросы;
- `BUG_REPORT.md` — единый баг-репорт по API и финансовой сверке.

## Запуск API-тестов

В первом терминале:

```text
py payment_sandbox.py
```

Во втором:

```text
py -m unittest -v api.test_payment_api
```

Тесты проверяют healthcheck, создание и получение платежа, идемпотентность,
повтор после неопределённого результата `500`, контроль побочных эффектов,
валидацию тела и суммы, валюты, неизвестные endpoint'ы и конкурентные запросы.
Падения фиксируют расхождения реализации с контрактом и не являются причиной
изменять `payment_sandbox.py`.

## Запуск реконсиляции

Реконсиляция сравнивает наши платёжные записи и выписку партнёра по полю
`ref`. Для каждой операции проверяется наличие записи в обеих системах,
уникальность идентификатора, совпадение суммы, валюты и статуса.

Результат разделяется на четыре категории: операции только у нас, операции
только у партнёра, дубликаты в выписке и расхождения полей у совпадающих
операций. Данные загружаются во временную SQLite-базу, поэтому исходные CSV
не изменяются.

```text
py reconciliation/reconcile.py
```

Скрипт сопоставляет CSV по `ref` и выводит операции только в одной системе,
дубликаты, а также расхождения суммы, валюты и статуса.

## Ограничения и что добавить при большем времени

Сервис хранит состояние только в памяти, поэтому отдельная проверка сохранения
идемпотентности после перезапуска не выполнялась. Также не задано правило
сверки дат и минимальная допустимая положительная сумма.

При большем времени добавил бы контрактные схемы, проверки параллельных
запросов с разными телами, тесты восстановления после перезапуска и CI-запуск.

## Опциональное задание 3: E2E

Python Playwright-сценарий находится в `e2e/test_checkout.py`, а действия и
локаторы вынесены в Page Object `e2e/checkout_page.py`. Он использует локальную
fixture `e2e/checkout.html` и проверяет ввод платёжных данных,
переход на подтверждение, финальный статус `Succeeded`, обязательность полей,
формат карты, даты, CVC и суммы.

Установка:

```text
py -m pip install -r requirements-e2e.txt
py -m playwright install chromium
```

Запуск в headless-режиме:

```text
py -m unittest -v e2e.test_checkout
```

Запуск с видимым браузером:

```powershell
$env:E2E_HEADLESS="0"
py -m unittest -v e2e.test_checkout
```

E2E-страница является локальной fixture и намеренно не подключена к
`payment_sandbox.py`; API покрывается отдельным black-box набором.
